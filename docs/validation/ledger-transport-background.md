## `elsepa-muffin-tin-inputs`

- **Claim:** an elementary catalog crystal's ELSEPA muffin-tin deck (`MUFFIN 1`, LDA-II absorption `MABS 2`, `VABSA 0.75`, `IHEF 0`) takes its radius (`RMUF`, cm) as half the nearest-neighbour distance computed from the catalog CIF; the crystal density `rho = 1e24 n A / N_A` enters only the table identity, since `elscata` has no density input and uses its own tabulated `VMOLE(Z)`, which affects only the stored absorption cross section; its production table joins those muffin-tin rows at or below 1 MeV verbatim to free-atom rows above, and compounds use free atoms for every element
- **Code:** `xsgen/elsepa/catalog.py::nearest_neighbour_distance_ang`, `::elemental_solid`, `::elemental_solid_for_composition`, `::joined_arrays`, `::resolve_layer_tables`; `xsgen/elsepa/deck.py::ElsepaDeck.muffin_tin`
- **Source:** F. Salvat, A. Jablonski, C. J. Powell, Comput. Phys. Commun. 165 (2005) 157, `10.1016/j.cpc.2004.09.006` (muffin-tin model for elementary solids, LDA absorption potential); ELSEPA 2020 README and `Al.in` example deck (touching-sphere radius, tabulated `DNNEL`)
- **Equation:** `RMUF = d_nn/2`, `d_nn = min_{i,j,R} |r_j + R - r_i|` over basis sites and lattice translations; `rho = 1e24 n A / N_A` [g/cm^3] with `n` in atoms/A^3
- **Assumptions:** equal touching spheres on every site, valid for a one-element crystal only (ELSEPA requires `NELEC = IZ`); `elscata` disables high-energy factorization in muffin-tin mode and its partial-wave series loses accuracy above about 1 MeV, so the solid-state rows stop there; below 100 eV the Dirac-Fock (`MELEC 4`)/muffin-tin treatment is not a supported physical model, so tables start at 100 eV
- **Limiting cases:** diamond-cubic Si and C reproduce ELSEPA's tabulated `DNNEL` (2.350, 1.540 A) and `a*sqrt(3)/4`; removing the long-range potential tail cuts the Si total elastic cross section by more than 10 % while the first transport cross section at 100 keV moves by less than 5 % (observed -32 % and -1.5 %)
- **Status:** rederived
- **Checks:** fixed-column muffin-tin deck fields; refusal of a non-positive radius, of factorization in muffin-tin mode, and of absorption strength without a model; distinct content keys for free-atom and muffin-tin decks; one-element layers matched to their crystal by element and number density (diamond and graphite stay distinct); compounds, media and unmatched layers get no muffin-tin table; join keeps the crossover node on the muffin-tin side and refuses mismatched angular grids; native-grid `4*pi*integral(DCS dmu)` closes to the muffin-tin total within `2e-3` at the 1 keV and 100 keV anchor energies (production tables reach `3.9e-3`, Si at 1 MeV: quadrature, not physics); missing tables fail with the fetch command
- **Anchor:** `tests/xsgen/test_elsepa_catalog.py`; opt-in real compiler comparison in `tests/xsgen/test_extern_codes.py::test_elsepa_muffin_tin_silicon_keeps_transport_and_cuts_the_total`
- **Notes:** The joined total cross section steps at 1 MeV: muffin-tin/free-atom ratio 0.685 (Si), 0.709 (black phosphorus), 0.522 (diamond), 0.463 (HOPG), while the first transport cross section stays within 1-3 %; energy interpolation turns the step into a ramp over one grid interval, which the sampler handles as an ordinary pair of valid CDFs. This is documented, not blended. `VABSD` is left to ELSEPA's tabulated excitation energy rather than the catalog band gap. The touching-sphere packing fraction is 0.17 for HOPG against 0.34 for Si and diamond, so the muffin-tin model is cruder for graphite; black phosphorus has no dedicated radius or matching test. **Fresh-context physics validation completed 2026-09-25:** radius, deck fields, join, and layer matching match an independent derivation; the 5x5x5 neighbour search is exact for all four crystals (`d_nn <= 2 min` plane spacing, with at least a threefold margin); the corrections above came from it. [Validation write-up](beam-transport/elsepa-muffin-tin-inputs.md). Verdict: `rederived`; only a human may mark this signed off.

## `elsepa-elastic-sampling`

- **Claim:** `elastic_model="elsepa"`, the default of every run built from `Numerics`, draws elastic flights from the macroscopic cross section `Sigma(E) = sum_i n_i sigma_i(E)` interpolated log-log between ELSEPA energy nodes, and polar deflections by exact inversion of each node's piecewise-linear normalized angular density `p(mu) = DCS(mu)/integral_0^1 DCS dmu`, with `mu = (1-cos(theta))/2` and quantiles interpolated linearly in `ln E` between nodes; energies outside the tables are refused, never extrapolated
- **Code:** `montecarlo/transport/scattering.py::elsepa_angular_pdf`, `::pack_elsepa_tables`, `::check_elsepa_coverage`, `::_elsepa_bracket`, `::_elsepa_invert_row`, `::_sample_cos_theta_elsepa`, `::_elsepa_rate_scalar`; CPU cores and the exact CUDA per-electron kernel in `montecarlo/transport/`; case selection in `montecarlo/runner/case_tables.py`
- **Source:** ELSEPA tables via [`elsepa-vendor-reference`](#elsepa-vendor-reference) and [`elsepa-muffin-tin-inputs`](#elsepa-muffin-tin-inputs); `dOmega = 4*pi*dmu` for an azimuthally symmetric DCS
- **Equation:** `ln Sigma(E) = (1-f) ln Sigma_k + f ln Sigma_{k+1}`, `f = (ln E - ln E_k)/(ln E_{k+1} - ln E_k)`; on a `mu` panel with `t = (mu - mu_j)/dmu` and `p = p_j + (p_{j+1} - p_j) t`, `F(t) = F_j + dmu (p_j t + (p_{j+1} - p_j) t^2/2)`, solved for `r = xi - F_j` by the cancellation-free root `t = 2r/(b + sqrt(b^2 + 2 dmu (p_{j+1} - p_j) r))` with `b = dmu p_j`; `mu(xi, E) = (1-f) mu_k(xi) + f mu_{k+1}(xi)`
- **Assumptions:** unpolarized electrons, unoriented targets (azimuth uniform); independent-atom additivity over a layer's elements; the DCS is piecewise linear in `mu` on ELSEPA's native grid (the same trapezoid measure the stored CDF uses); all tables share one angular grid
- **Limiting cases:** at a node the sample reproduces that node's tabulated CDF exactly (Kolmogorov distance below the 99 % critical value for 2e5 draws); a screened-Rutherford-shaped table reproduces the analytic first moment `<1-cos theta> = 2a[(1+a) ln(1+1/a) - 1]` within 0.5 %; on the real vendor Hg 1 keV DCS, sampled `<1 - P_l(cos theta)>` reproduces ELSEPA's own `sigma_l/sigma` for l = 1, 2 to about 2e-5 (tested at 1e-4); end to end, SR-shaped ELSEPA tables reproduce the analytic `"sr"` model's backscatter fraction (within 4 sigma) and mean path length (3 %) on the lockstep and per-electron cores; `xi = 0` gives `cos theta = 1`; each element's rate is exact at its nodes and geometric at the log midpoint, and a compound's total is the sum of those per-element interpolants
- **Status:** rederived
- **Checks:** normalized pdf/CDF match the stored xsgen CDF to `1e-14`; samples monotone in `xi`; packing refuses mismatched angular grids, element counts, non-increasing energies and non-positive totals; `elastic_model="elsepa"` requires tables and covering energies; flight diagnostics use the ELSEPA hazard; opt-in model forks run identity and case content keys only when on, and the resolved tables join the xsgen identity markers
- **Anchor:** `tests/montecarlo/test_elsepa_elastic.py`; `tests/montecarlo/test_elastic_model_case.py`; CUDA-gated `tests/montecarlo/test_elsepa_elastic.py::test_cuda_elsepa_first_step_matches_the_cpu_reference`, `::test_cuda_elsepa_agrees_statistically_with_the_cpu_core`
- **Stated tolerance:** over all 28 released tables (24 transport elements, 100 eV-100 MeV; 4 elementary-crystal muffin-tin tables, 100 eV-1 MeV), the exact moments of the sampled piecewise-linear density reproduce ELSEPA's `sigma_1/sigma` and `sigma_2/sigma` within 0.56 % at or below 1 MeV, 0.89 % at 1-10 MeV and 0.59 % above 10 MeV (measured 2026-09-25). Above about 10 MeV the forward peak outruns ELSEPA's native 606-point angular grid, so the trapezoid `4*pi*integral(DCS dmu)` exceeds ELSEPA's total by 0.7-1.4 % (muffin-tin tables: at most 0.39 %); the flight rate uses ELSEPA's total directly, so only the angular shape carries that error.
- **Notes:** Default since issue #89 for runs built from `Numerics`, `Settings`, profiles and `build_cases`; the explicit `"mott"` model keeps its historical case payload and run identity, and low-level `simulate_trajectories` now also defaults to `"elsepa"` (it was `"mott"` before #263), resolving the stored tables when none are passed. Tables install with `pyrite tables fetch elsepa` from a pinned release (`data/xsgen/elsepa-tables.json`, 25.2 MB archive); a missing table fails with that command rather than falling back. The transport LUT is bypassed under ELSEPA. The CUDA anchors passed on an RTX 5080 (CuPy 14.2.0, driver 610.47, `srun -p gpu`, 2026-09-25) at `b20fb6dc`, whose CUDA kernel and ELSEPA sampling code are unchanged at this row's commit; the full `-m hardware` suite gave 71 passed, 2 skipped (Intel SYCL opt-in, and `test_segment_staging.py`, which reported no CUDA device or a NumPy-pinned session). ## `inelastic-angular-deflection`

- **Source:** H. A. Bethe, Phys. Rev. 89 (1953) 1256 (`Z^2 -> Z(Z+1)`); I. Kawrakow, Med. Phys. 24 (1997) 505, `10.1118/1.597933`; EGSnrc PIRS-701 (2026-08-26) Eqs. 4.7.6-4.7.8 (Moliere `eta`) and 4.7.21-4.7.22 (`g_M`, `g_R`); Geant4 11.4.2 `G4eDPWAElasticDCS::InitSCPCorrection` and `G4eDPWACoulombScatteringModel::ComputeCrossSectionPerAtom` (the #183 reference's `isscpcor`)
- **Equation:** [Atomic-electron angular deflection](../physics/beam-transport/atomic-electron-deflection.md) Eqs. `eq-aed-rate-scale` to `eq-aed-eta`
- **Assumptions:** atomic-electron deflection follows the active elastic model's nuclear angular law (Bethe single-parameter treatment, not Fano's separate logarithm); hard share from free-electron Moller kinematics, binding ignored; `xi` is a layer property through `eta`; the energy-dependent shell-mode `xi` is evaluated on ELSEPA energy nodes and interpolated log-log with the rate, and the analytic `sr`/`mott` rates take only the constant continuous-mode factor
- **Limiting cases:** `T <= 2 T_c` or `T_c = inf` gives `xi = 1`; `Z -> inf` gives factor 1; `g_M >= g_R` gives `xi = 0` (Si, `W_c = 50` eV, from 315 eV up); opt-out reproduces elastic-only transport bit for bit

- **Checks:** `g_M` matches a direct quadrature of the Moller DCS times the primary's `sin^2 theta` to `1e-9` at five `(tau, tau_c)`; `g_R` matches a direct `sin^2` moment of the screened-Rutherford law to `1e-8`; per-element `xi` and factor for Si and W at 10-800 keV and cutoffs 50 eV-10 keV match an independent evaluation; `xi` falls with energy and rises with cutoff; continuous-mode factor exactly `(Z+1)/Z` on the SR and Mott coefficients, denominators and screening untouched; ELSEPA log-rate nodes shift by `ln(1 + xi/Z)` with the angular CDF unchanged; first-flight mean length shrinks by exactly 14/15 for Si at a fixed seed; default `None` transport bit-identical to explicit opt-out; `"none"` reproduces the pre-#317 hopg dataset digest and case content key; shell transport with `sr`/`mott` rejected, Mott run cases resolved to shell keep elastic-only deflection with a warning

- **Notes:** Issue #317, found in #183. Cross-references: [`electron-transport`](#electron-transport) (transport loop), [`elsepa-elastic-sampling`](#elsepa-elastic-sampling) (rate nodes and angular law), [`shell-soft-hard-transport`](#shell-soft-hard-transport) (hard collisions that deflect explicitly). ## `bremslib-radiative-event-spectrum`

- **Claim:** Post-transport scoring separates sampled hard photons from soft track-length emission at the photon cutoff `kc`; a bin that straddles `kc` takes its below-cutoff width share of the soft node density plus the hard events above `kc`. - **Equation:** `p(Omega|T,k) = [d²σ/(dk dOmega)]/[dσ/dk]`; a hard event of energy `k` contributes `p(Omega|T,k) exp(-Σ_l mu_l(k) L_l)/(Ne Δk_bin)` to its photon-energy bin, where `L_l` is the escape path through layer `l` from the event endpoint. Track-length scoring is zero in bins wholly above `kc`; in the bin `[ε_j, ε_j+Δk_j)` containing `kc` it is `f(E_j)(kc-ε_j)/Δk_j`, where `f(E_j)` is the soft node estimate.
- **Assumptions:** hard event frequency and photon energy have already been sampled from the parent BremsLib SDCS; planar layers with an optional finite rectangular footprint (no grooves), Beer–Lambert escape, azimuthally symmetric DDCS, positive `kc`, with every bin wholly below it soft and every bin wholly above it hard (below the grid every bin is hard, above it every bin is soft); within a straddling bin the soft density is taken as constant at its node value.

The sample violates `cbs-amplitude`'s own perturbative validity condition `|U_g| g²/(γ mc² (v·g)²) ≪ 1` by a factor 15.6, so such samples are rejected, not computed. **Fixed here.** `_in_medium_kinematics` now checks convergence instead of assuming it: the last fixed-point pass must move `denom` by less than `_RESONANCE_ROOT_RTOL = 1e-3`, and pairs that fail carry NaN out of `denom` and drop on the caller's existing finite mask — the same route out-of-range tabulation energies already take.
