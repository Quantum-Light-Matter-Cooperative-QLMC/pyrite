# Repository map: Entry points

Detail page of the [repository map](../repo_map.md). Start from the front page; module paths are relative to `src/pyrite/`.

## Entry points

- **`pyrite.quantum`** remains a module and owns quantum configuration plus a curated lazy facade for portable `TransverseStateSpec`, nonportable runtime factories, planar projection, and selected experimental planar/axial solvers and diagnostics. Definitions remain in `quantum_state`, `planar_source`, and `montecarlo.channeling` leaves; aliases preserve object/pickle identity and production admission. `api-surface.toml` governs this module through `package_exports`; the [quantum API contracts](../reference/quantum-api.md) lists status, units, and bounded examples.
- **Advanced scientific facades**: `transport/__init__.py` lazily aliases the supported lowered `Case`, trajectory simulation and saved-capture summaries; `radiation/__init__.py` aliases deterministic line energies, three supported spectrum functions and experimental directional sources. No engine moves or numerical changes; existing implementation paths retain compatibility. `DirectionalSpectrum` remains owned by `results.directional`. Contracts and migration: [advanced API](../reference/python-api/transport.md#advanced-transport-and-radiation).

- **`pyrite` console script** → `cli:main` (`pyproject.toml [project.scripts]`), lazy Click dispatch for user workflows including `physics` and `numerics`; remote lifecycle is canonical at `remote job`, with the former root `job` hidden through 0.17.0. Retired top-level setup, completion, performance, energy-grid, scan, analyze/export, and flat checkpoint spellings remain hidden compatibility aliases where the D7 registry documents a replacement. Checked user-facing inventory: [CLI reference](../repo-design/cli/cli-reference.md).
- **`import pyrite`** → `__init__`: lightweight lazy exports for `Beam`, target variants, shared `SubstanceRef`/`RectangularBody` descriptions and `Target`/`Filter` roles, `Detector`, `Scene`, path-addressed `Sweep`, `Physics`, `Numerics`, `CxrReflections`, `Precision`, `Analysis`, `Result`, and `simulate`.
- **`pyrite.simulate(scene)` / `pyrite.simulate(beam, target, detector, ...)`** → `api:simulate`: lower one scalar scene to the typed `Case`, run it without checkpoint I/O, and return response-free source arrays plus resolved provenance in `Result`.
- **Opt-in photon aperture** → `_photon_config.PhotonTransport`, `campaign.photon_cases`, `montecarlo.runner.photon_aperture`: lower a scalar physical Scene's selected CPU/CUDA photon source, share its primary rows with directional scoring, and expose the separate `Result.aperture` tally. `_photon_support` owns shared reference identity/preparation; `results.aperture` owns checked checkpoint reconstruction and histogram/current views. Optional `photon.h5` and CAS payloads retain original pins; full artifact replay supports the mode, bounded replay refuses it. Contract: [photon aperture observations](../repo-design/compute/photon-aperture.md).
- **`pyrite.photon_energies(materials, beam_energy_eV, ...)`** → `materials.emission:photon_energies`: deterministic vacuum line-centre arrays with paired NumPy broadcasting or Cartesian grids; catalogue cut/reflection resolution, no transport or accelerator initialization.
- **`pyrite profile ...`** → `cli.commands.profile`: manage named campaign defaults and material membership through `set|add|remove`; an absent membership key means all catalog materials. Bundled demo profiles are read-only; edits write to the user catalog layer. **`pyrite-dev profile ...`** → `devtools.dev_cli:cmd_profile`: the same tree against the bundled catalog for maintaining the shipped demos. **`pyrite-dev beam ...`** and **`pyrite-dev detector ...`** likewise maintain packaged instrument examples; user commands copy them with `create NAME --from SOURCE` and edit the user layer.
- **`pyrite profile detector list|show|add|set|reset|rm|migrate`** → `cli.commands._profile_detectors` (registered on `profile`): detector collection membership, inline scalar/pixel settings, optional-section resets, and explicit legacy migration, with storage/merge primitives in `campaign/profile_detectors.py`. An acquisition makes the profile a counting observation whose projection supersedes the scalar detector for sweeps. **`pyrite profile filter add|set|rm|list|show`** → `cli.commands._profile_filters` (registered on `profile`): edits ordered plates and no longer touches the physical detector. **`pyrite numerics cxr-grid show|set|reset`** → `cli.commands._profile_cxr_grid` (registered on `profile`): the `[profiles.NAME.line_grid_policy]` selectors and the profile's grid-source summary; selector-combination checks shared with `_cxr_grid_policy.check_selector_combination`, edit primitives in `campaign/profile_cxr_grid.py`. Settings inventory: `docs/repo-design/profile-settings.md`.
- **`pyrite profile create NAME [--from SOURCE]`** → `cli.commands.profile` and `campaign.profile_lifecycle`: without `--from`, copies packaged `standard` sweep ranges, applicable material overrides, and membership into a new profile; with `--from`, explicitly clones SOURCE except material overrides. Omitted bremsstrahlung grids resolve to the built-in 25 eV default. Omitted detector and physical-detector fields resolve to code defaults and none, respectively.
- **`pyrite material show MATERIAL`** → `cli.commands.material`: inspect intrinsic composition, density and identity. **`pyrite profile ranges show PROFILE MATERIAL`** inspects effective campaign ranges/overrides; `material show --profile` remains a warning compatibility view. `pyrite material blaze MATERIAL ...` routes to the specialized blazed sweep. Hidden compatibility aliases remain under `pyrite sweep`.
- **`pyrite material validate [catalog]`** → `cli.commands.check_config:_run`: validate bundled offline catalog or explicit complete catalog without starting simulation; hidden alias: `pyrite check-config`.
- **`pyrite checkpoint ...`** → `cli.commands.checkpoint:command`: grouped local checkpoint shrink, component recompute, list, and `archive store|restore|list|merge` operations. `checkpoint recompute brem|line -R[=TARGET]` reuses the remote SLURM orchestrators with uniform `--wait` / `--detach`; hidden compatibility paths: `remote rebrem`, `remote reline`.
- **`pyrite checkpoint gc [--all | --profile NAME] [--yes]`** → `cli.commands.cleanup:gc_command`: preview or atomically rewrite current named-profile checkpoints, retaining only records whose full case payload exactly matches current profile resolution. Hidden compatibility aliases: `pyrite checkpoint prune`, `pyrite prune`.
- **`pyrite checkpoint rm [MATERIAL]... | --profile NAME | --all [--yes]`** → `cli.commands.cleanup:rm_command`: delete explicitly selected local datasets and the CAS blobs they alone kept reachable. Hidden compatibility alias: `pyrite checkpoint clear`.
- **`pyrite config set|unset|get|keys|list|explain|setup|completion`** → `cli.commands.config` + `cli._config`: persist and inspect the current profile and remote target, select the local compute backend, and manage shell completion. Values resolve through the shared per-call > `PYRITE_*` environment > config store > built-in precedence chain. The user store is written atomically under Click's platform config dir.
- **`-o/--output table|json`** → `console.output.output_option`: shared output selector on JSON-capable non-interactive commands. `table` is the human default, profile summaries and ephemeral runs additionally retain distinct human-only `wide` output; only `json` carries the stable versioned envelope contract. The retired `--json` spelling remains unsupported.
- **`pyrite run [PROFILE] [-m MATERIAL] [-R[=TARGET]]`** → local `runs.scan:main` → `runs.run.run_sweep`, or the existing SSH/SLURM submitter when `--remote` is present. An omitted profile uses the configured current profile; bare `--remote` uses the configured target; an explicit value is validated and scoped to that invocation. Remote runs accept uniform `--wait` / `--detach`; local runs reject them. Local output is canonical `checkpoints/<material>/{line,brem,characteristic}.h5` or an identity-qualified variant directory. Box shim: `python -m pyrite._entry.scan`.
- **`pyrite-dev perf [PROFILE] [-m MATERIAL] [-R[=TARGET]]`** → the same run machinery with compute-performance telemetry enabled and shared-cache access disabled by default. Telemetry interval, GPU chunk pins, Nsight capture, and remote CPU profiling are developer-only options on this command.
- **`pyrite numerics energy-grid derive [-R[=TARGET]]`** → `energy_grid._command` → local derivation or the existing sliced SSH/SLURM grid job. Remote derivation waits and pulls its JSON by default, then installs immutable artifacts and repoints `--profile NAME` (or the configured current profile); local completion does the same. `--detach` returns after submission without installing. Hidden compatibility aliases remain hidden below `pyrite energy-grid`.
- **`pyrite numerics energy-grid show|line show|brem show`** → `cli.commands.energy_grid`: inspect resolved detector bins. Automatic runs never read derivation batch presets; specialist derivation requires explicit material and energy selection.
- **`pyrite-dev energy-grid add|rm|verify|gc|line set|brem set`** → `energy_grid._command` → immutable `energy-grid-artifacts/<first2>/<sha256>.json` objects plus mutable `profiles.NAME.energy_grid_refs`. `add`/manual setters/rm create replacement objects and repoint only the selected profile; `verify` checks bytes and refs; `gc` reclaims unreachable objects after a 14-day grace window. Hidden D7 hidden user-CLI aliases: `apply` → `add`, `line delete` → `rm`.
- **`pyrite-dev performance list|analyze|rm`** → `cli.commands.performance`: inspect and reclaim derived compute-performance artifacts. The former top-level `pyrite performance` group is a hidden D7 alias.
- **Marimo apps**: `src/pyrite/apps/scan_app.py` (sweep runner → checkpoint), `src/pyrite/apps/analysis_app.py` (checkpoint-driven Altair figures in three views — Spectra, Map, Detectors — each gated so only the selected one computes, reading one shared slice from `mo.sidebar`), `src/pyrite/apps/pixel_app.py` (stored pixel-detector observations for one checkpoint stem; never loads the checkpoint), `src/pyrite/apps/compare_app.py` (case basket across checkpoints + cross-material comparison over every catalog checkpoint), `src/pyrite/apps/trace_app.py` (3D trajectory animation + crystal-lattice viewer; runs transport directly from catalog scan grids, no checkpoint needed), `src/pyrite/apps/validation_app.py` (validation-study interface). Shared pieces: `src/pyrite/apps/_design.py` (page chrome), `src/pyrite/apps/_widgets.py` (`MaterialSelect` anywidget). Scan, analysis, and trace apps read per-material grids in `config.py`. The pixel app is wired by `apps/analysis_ui/pixels.py` (observation discovery/loading, controls, image resolution) and rendered by `apps/analysis_ui/views/pixels.py`; the compare app renders `apps/analysis_ui/views/cases.py` and `views/materials.py`. Those three view modules are imported by submodule path, not re-exported from `analysis_ui.views`, so the analysis app never loads them. All three checkpoint apps share the Material + Checkpoint picker (`analysis_ui/pickers.py`: `make_checkpoint_picker`, which lists every stem with its face and defaults only to the standard flat run) and loading (`data.py`: `load_context`, `selected_checkpoint_stem`, `slice_results`).
- **`pyrite app analysis launch [material]`** → `analyze:_cli`: launch or smoke-test the analysis app with explicit or persisted initial material; `pyrite app analysis export` writes static HTML. The implicit launch form is a hidden-behavior compatibility path and warns.
- **`pyrite app validation launch`** → `check:_cli`: launch the validation app; `pyrite app validation export` writes cached literature-validation figures. The same explicit `launch|export` shape applies to `pyrite app viewer`.
- **`pyrite remote ...`** → `remote:*`: optional SSH/SLURM resources for lab GPU box. Canonical profile and Zhai reproduction submissions are `pyrite run --remote` and `pyrite run --preset zhai --remote`; hidden warning aliases preserve `remote run`, `remote validate`, and `remote check`. Resource commands remain here, while retired `jobs`, `status`, `logs`, and `stop` paths are hidden aliases of the canonical top-level job lifecycle. `remote pull --preset zhai` retrieves an existing reproduction cache; `remote gc` applies profile-aware checkpoint pruning under remote stem reservations and releases orphaned reservations, replacing the hidden `remote prune` and `remote reap` aliases; `remote rm` deletes remote checkpoints (hidden alias `remote clear`); `check` remains a hidden alias.
- **`pyrite remote job list|status|logs|attach|stop`** → `cli.commands.job`: one lifecycle for run, grid, recompute, and validation jobs. `list --kind` normalizes legacy submitter metadata to `run|grid|recompute|validate`; destructive stop targets exactly one job ID, profile, or all live jobs.
- **`pyrite run ... --trajectories DIR [--overwrite-trajectories]`** → `runs.scan._run_material` builds a `montecarlo.trajectories.TrajectoryCapture` rooted at `DIR/<stem>/`; off by default; remote submissions forward the root to the host and leave captures there. **`pyrite trajectories ls [DIR...]` / `info ARTIFACT`** → `cli.commands.trajectories` → `montecarlo.trajectory_inventory` (`discover_artifacts` skips partial/foreign files; `describe_artifact` reads headers, node metadata and bounded ID-column scans only) (#397). **`pyrite trajectories export ARTIFACT... [--history|--track|--first|--sample]`** (deprecated alias `checkpoint export-trajectories`) → `cli.commands.trajectories.export_command` → `montecarlo.trajectory_selection.select_trajectories` (whole-history/track stored-row runs) → `montecarlo.trajectory_export.export_segments_vtp` (streams only the selected runs). `--paraview-script` prints the bundled ParaView preset `data/paraview/pyrite_trajectories.py` (runs under `pvpython`/`pvbatch`, never imported by PyRITE). **`pyrite trajectories score ARTIFACT...`** (deprecated alias `checkpoint score-trajectories`) → `cli.commands.trajectories.score_command` → `checkpoints.trajectory_scoring` (plan/check every artifact and target, then `runner.stream_spectrum_from_artifact` per case into `<checkpoint-dir>/<stem>`; no transport, no shared cache) (#186).
- **Trajectory scenes**: `instrument.scene` snapshots downstream geometry separately from the transport case. `montecarlo.trajectory_scene` adds opt-in, independently viewable close-up/instrument VTK manifests through `trajectories export --scene`. Numeric meshes, groove ribbons and transforms live in `_scene_geometry`, shared with `plots.plotly.trajectories`; see [scene design](../repo-design/storage/trajectory-scenes.md).
- **Trajectory demo**: bundled `data/catalog/profiles/trajectory_demo.toml` and its named beam run one 30 keV / 2 µm HOPG case with 100 fixed histories and a round 1 µm FWHM spot; `pyrite run trajectory_demo --trajectories DIR` exercises capture without `--quick` or profile edits.
- **Channeling demo**: bundled `data/catalog/profiles/channeling_demo.toml` runs one fixed-count 17 MeV / 2 µm Si(1-10) planar channeling case on the packaged on-axis `detectors/forward.toml` (3 × 3 mm at 1 m) with explicit 1–24 keV line and coarse continuum grids; workflow in [experimental planar channeling](../guides/experimental-planar-channeling.md).
- **`pyrite checkpoint slim <checkpoint-dir> [--grid]`** → `slim:slim_checkpoint` → `results.slim_results`: shrink a checkpoint HDF5 artifact for transfer (drop wide-brem / float32 / filter configs; `--grid` keep only material's current-grid configs).
- **`pyrite checkpoint list`** → `archive:list_command` (active slots); **`pyrite checkpoint archive store|restore|list|merge`** → `archive:*`: local checkpoint shelf — copy active slot `checkpoints/<stem>/` to/from long-term `checkpoints/archive/<label>/`; `merge` combines a shelved checkpoint back into the active slot for the same material. Retired top-level spellings are hidden compatibility aliases.
- **Sweep worker**: `montecarlo.run_case` (module-level so it pickles into `run_cases` process pool).
